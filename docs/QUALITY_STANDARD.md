# Quality Standard

This project should be developed as a high-quality product, not a disposable demo.

## Core Principle

If speed conflicts with product quality, choose product quality. If efficiency does not reduce the final product quality, choose the more stable and efficient implementation path.

## Product Quality Requirements

- Stable local workflow
- Clear UI
- Clean folder structure
- Safe public showcase version
- No private data leakage
- Clear documentation
- Reusable launchers
- Maintainable code structure
- Good report readability
- Long-term extensibility

## UI Quality Requirements

- Apple-style clean layout
- Clear function entry points
- Useful color accents
- Rounded cards
- Strong visual hierarchy
- Not empty or vague
- Core buttons visible on the dashboard

## Engineering Quality Requirements

- Avoid fragile PowerShell multiline input when possible
- Prefer stable patch scripts
- Keep input and output folders separated
- Keep generated files out of public GitHub
- Keep API features optional
- Keep local mode fully usable without paid API credits
